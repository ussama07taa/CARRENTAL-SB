# تصور البنية والشاشات ومراحل إنجاز نظام الوكالة

> وثيقة تاريخية متجاوزة ابتداءً من ١٦ أكتوبر ٢٠٢٦. المرجع الجاري هو [المرجع الموحد](master-specification-ar.md)، بما فيه القرارات المعلقة. لا تعتمد القواعد المخالفة هنا عند التنفيذ.

تاريخ الإعداد: ١٥ أكتوبر ٢٠٢٦

هاد التصور مبني على [متطلبات النظام المتفق عليها](business-requirements-ar.md). الهدف هو بناء نظام تسيير كامل لوكالة واحدة، من سبع سيارات حتى ثلاثمائة وأكثر، بمطور واحد ومساعد. الاقتراح التقني هنا للمراجعة، ماشي تغيير منفذ فتعليمات المشروع. ما كاين لا كود جديد لا قاعدة بيانات لا نشر.

## الاختيار التقني الحالي

الاختيار الأخير للمشروع هو خادم Laravel واحد لقواعد العمل، وموقع Next.js مستقل ولوحة تسيير Next.js مستقلة، بجوج بـTypeScript، داخل مستودع واحد. قاعدة PostgreSQL واحدة هي مصدر البيانات، وLaravel هو المرجع الرسمي للحسابات والتوفر والصلاحيات.

الواجهتان تتواصلان مع Laravel عبر واجهة موثقة تحت المسار المتفق عليه. معاينة الحساب فالواجهة ما تعوضش إعادة التحقق والحساب فالخادم. الموقع بالعربية والفرنسية، واللوحة بالفرنسية فقط. مجالات العمل داخل Laravel تبقى وحدات داخل نفس التطبيق، ماشي خدمات مصغرة.

اقتراح Livewire السابق متجاوز بعد توضيح التوجه الطويل المدى واحتمال انضمام مطورين. تكلفة الفصل فالمصادقة وتعاقد البيانات والنشر كتدخل ضمن الخطة؛ ما نعتابروش اختيار Next.js ضماناً للأداء أو إعفاءً من الاختبارات.

Next.js كيدعم أجزاء من الواجهة فالخادم وأجزاء تفاعلية فالمتصفح؛ اختيار موضع كل جزء كيكون حسب الشاشة، مع منع تخزين مؤقت مشترك لبيانات مالية أو شخصية. [مرجع الواجهة](https://nextjs.org/docs/app/getting-started/server-and-client-components)

## شنو نبسطو وشنو نحافظو عليه

| الجانب | الاقتراح |
|---|---|
| التطبيقات | خادم Laravel، موقع Next.js ولوحة Next.js داخل مستودع واحد؛ تنظيم الحزم بـpnpm وTurborepo |
| الموقع | صفحات خادم بالعربية والفرنسية، مع دعم اتجاه العربية ومسار طلب واضح |
| لوحة التسيير | واجهة فرنسية متجاوبة للحاسوب والهاتف، بشاشات مخصصة للخدمة اليومية |
| تسجيل الدخول | Sanctum بجلسة وملفات ارتباط محمية، وضبط طلبات الواجهة وحماية الطلبات والنطاقات؛ تمرير الجلسة صراحة عند عرض صفحات داخلية من الخادم |
| قاعدة البيانات | PostgreSQL مدارة مع امتداد منع التعارض المطلوب؛ اختبارات على نفس محرك البيانات |
| ملكية البيانات | الاحتفاظ بربط كل بيانات الوكالة بصاحبها وفحص العزل، بلا بناء اشتراكات متعددة الوكالات |
| قواعد العمل | خدمات واضحة للحجز والحسابات والرجوع والتسويات، ما تتكتبش داخل الأزرار أو قوالب الصفحات |
| الملفات | تخزين منفصل للصور العامة والملفات الخاصة، مع تحقق من الصلاحية قبل الوصول |
| الوثائق | Browsershot للعقود والفواتير، مع حفظ الملف الصادر الأصلي وبصمته |
| المهام الخلفية | Redis وHorizon، مع عامل محدود خاص بالوثائق وعامل للمهام العادية؛ تأجيل فئة عاجلة بلا استعمال حقيقي |
| التنبيهات | استعلام خفيف دوري داخل اللوحة؛ ما كاينش اتصال لحظي دائم فالنسخة الأولى |
| الرسائل | رابط يدوي، مع تأكيد الموظف للإرسال؛ ما كاينش إرسال آلي |
| المشاركة | حزمة صغيرة لمكونات مستعملة فعلاً فالواجهتين، وحزمة أنواع مولدة من وصف OpenAPI |
| واجهة برمجية | مسارات عامة محدودة للموقع ومسارات مصادق عليها للوحة؛ Laravel يعيد فحص كل صلاحية وحساب |

Next.js كيحتاج بناء وتشغيلاً مناسبين للواجهات، وBrowsershot كيحتاج بيئة Node ومتصفحاً آلياً داخل عامل الوثائق. نحدد موارد كل عملية ونفصل أعطال إصدار الوثائق عن خدمة الطلبات. [متطلبات إصدار الوثائق](https://spatie.be/docs/browsershot/v4/requirements)

نختارو إصداراً مستقراً ومتوافقاً عند البداية، ونثبتو الإصدارات الفعلية فملفات الاعتمادات ونسجلوا طريقة الترقية. التحديث ما يدخلش تلقائياً للإنتاج بلا اختبار.

## تنظيم العمل داخل التطبيق

نقسمو المسؤوليات لمجالات داخل نفس التطبيق. هادشي تنظيم للكود والاختبارات، ماشي خدمات مستقلة ولا خوادم متعددة.

| المجال | المسؤولية |
|---|---|
| الحجوزات والكراء | الطلب، الحجز المؤقت، التخصيص، التأكيد، التمديد، التبديل، التسليم والرجوع |
| السيارات | الأنواع والوحدات والوثائق والعداد والصيانة وفترات التوقف |
| الزبناء | صاحب العقد والسائقون والتحقق والملاحظات والمنع المبرر |
| الحسابات | الأثمنة، بنود المستحقات، الأداءات، الضمان، التسويات والمصاريف والصندوق |
| التمويل | عقود القروض، الجداول، الأقساط وتخصيص الأداءات |
| الحوادث والمتابعة | الواقعة، المسؤولية، الوثائق، الإصلاحات، التأمين والمخالفات |
| الوثائق والتواصل | إصدارات العقود والفواتير والتوقيعات والروابط والرسائل اليدوية |
| الإدارة والتقارير | المستخدمون والصلاحيات والإعدادات والتقارير وسجل القرارات |

التقارير كتقرأ من المعطيات الأصلية وما كتخلقش حساباً آخر مخالفاً. إصدار وثيقة ما كيحسبش الثمن من جديد. شاشة الأداء كتستعمل نفس عملية الأداء اللي كتستعملها شاشة الكراء.

ما نحتاجوش واجهة تجريد لكل صنف أو منعاً مطلقاً لأي علاقة بين المجالات. العمليات اللي كتمس أكثر من مجال كتجمعها خدمة واضحة ومعاملة بيانات واحدة عند الحاجة، وباختبار كيحمي القاعدة.

## خريطة الشاشات الداخلية

الأسماء هنا بالعربية للشرح. العناوين الفعلية داخل المنتج تبقى بالفرنسية حسب القرار المعتمد.

### القائمة الرئيسية

| المدخل | شنو يلقى فيه المستخدم |
|---|---|
| اليوم | المغادرات والرجوع والطلبات والتأخر والتنبيهات؛ المالية العامة للمسؤول فقط |
| الجدول والحجوزات | عرض زمني أو قائمة، البحث، الحجز الجديد وفتح ملف الكراء |
| السيارات | اللائحة وملف كل سيارة، مع تبويبات الوثائق والصيانة والتوقف والتمويل والنتائج حسب الصلاحية |
| الزبناء | البحث، الملفات، السائقون والتاريخ والمبالغ المرتبطة بالكراءات المسموح بها |
| الفلوس | الأداءات والضمانات والمصاريف والأقساط والصندوق؛ المداخل تتفلتر حسب الصلاحية |
| الملفات والمتابعة | الحوادث والتأمين والمخالفات والخلافات والتحصيل |
| التقارير | تقارير السيارة والوكالة والفترات للمسؤول |
| الإعدادات | الأثمنة والمواسم والكيلومترات والقواعد والحسابات، للمسؤول |

الحادث أو القرض أو المخالفة عندهم تفاصيل مرتبطة بالسيارة أو الكراء. ما نفرضوش على المستخدم يكتب نفس السيارة والزبون من جديد إلا فتح العملية من الملف المرتبط.

### لوحة اليوم

أول ما يشوف الموظف هو ما يحتاج تدخلاً: سيارات خاصها تخرج أو ترجع، حجز مؤقت قرب يسالي، طلب خاصو اتصال، سيارة متأخرة، أو موعد صيانة. كل تنبيه فيه الوقت والحالة وزر يفتح الملف المعني.

المسؤول كيشوف زيادة عليها الأقساط والمصاريف المستحقة والمبالغ الواجب ردها والفروق فالصندوق. ما نملؤوش الشاشة برسوم مالية ما كتعاونش الخدمة اليومية.

التنبيه ما يختفيش لمجرد فتحه؛ يزول أو تتبدل حالته عند معالجة سببه. الإشعارات المعادة ما تخلقش أحداثاً مالية جديدة.

### الجدول والحجز الجديد

الجدول يعرض فترة محددة ومجموعة سيارات حسب الفلتر، ما يحملش ثلاثمائة سيارة وتاريخها كامل دفعة واحدة. كاين عرض قائمة بديل للهاتف والبحث بالرقم والاسم واللوحة.

الحجز الجديد فثلاث مراحل واضحة:

١. الزبون والسائق، مصدر الطلب، لغة الوثائق، وتواريخ الكراء.

٢. النوع والسيارة المتاحة، عرض الأثمنة، حصة الكيلومترات، ومبلغ الضمان الذي يدخله الموظف أو المسؤول.

٣. مراجعة الملخص، التفعيل المؤقت أو التأكيد بعد تحقق كامل الأداء، مع الوثائق والتواصل.

المبلغ المقترح من الواجهة ما نعتمدوش عليه بلا إعادة حساب على الخادم. إذا تبدلت المعطيات منذ فتح الشاشة، نعرض فرقاً واضحاً قبل التأكيد. الموقع ما كيضمنش وحدة فعلية قبل التخصيص والتأكيد.

### ملف الكراء هو الشاشة المركزية

أعلى الملف: المرجع، الزبون، السيارة الحالية، الحالة، التواريخ، والمبلغ المتبقي. تحته تبويبات صغيرة:

- الملخص والاتفاق: الأثمنة، المدة، الكيلومترات، لغة الزبون وشروطه المجمدة.
- الأداء والضمان: مبالغ مستحقة ومحصلة ومطلوبة للإرجاع، والضمان منفصل بوضوح.
- التسليم والرجوع: الوثائق المتحقق منها والصور والتوقيع والعداد والوقود.
- التعديلات: تمديد أو تبديل أو تغيير موعد، مع الفرق والتبرير.
- الوثائق والتواصل: العقود والفواتير وإصدارات التعديلات وروابط الإرسال اليدوي.
- المتابعة والتاريخ: الحوادث والخلافات والمخالفات والقرارات ومن قام بها.

الأزرار كتتبدل حسب المرحلة والصلاحية. زر التسليم يبين الشروط الناقصة بالاسم، ما يعطيش غير رسالة رفض عامة. الإجراء الحساس كيعرض أثره المالي قبل التأكيد، وأي ضغط مكرر ما يكرر العملية.

### التسليم والرجوع

التسليم مسار قصير: تحقق السائق، الأداء والضمان، حالة السيارة، ثم العقد وتأكيد الخروج الفعلي. ما ننسجلوش خروجاً ناجحاً إذا التوقيع أو باقي الشروط ناقصين.

الرجوع يسجل الوقت والعداد والوقود والحالة أولاً، ثم الرسوم والتسوية والضمان. تسجيل الرجوع المادي ما ينتظرش انتهاء نزاع مالي. واجهة النزاع تبين بوضوح شنو معتمد وشنو مختلف عليه.

عند تبديل السيارة، الفحص ديال الأولى والخروج ديال الثانية مرتبطان بنفس الكراء، مع فترات استعمال واضحة. الجاهزية للكراء من بعد الرجوع كتراعي التحضير والسلامة والصيانة.

### ملف السيارة

يجمع التعريف والصورة واللوحة والحالة الحالية، ثم الحجوزات، وثائق الصلاحية، الصيانة، الحوادث، القرض والمصاريف. الموظف ما كيتوصلش بمعلومات التمويل والنتائج العامة من الخادم إذا ما عندوش صلاحية، ماشي غير إخفاؤها فالشاشة.

كل موعد صيانة كيبين أساسه: تاريخ أو عداد. فشل تحديث العداد أو قراءة غير منطقية كيتطلب تصحيحاً موثقاً، ما يتقبلش بصمت.

### الفلوس والمتابعة

لائحة الأداءات كتفتح العملية الأصلية. إدخال المصروف يحدد السيارة أو الوكالة والوثيقة والجهة والمبلغ وحالة الأداء. جدول القرض كيقبل المواعيد والمبالغ الفعلية لكل سيارة. شاشة الصندوق كتقارن النقد المتوقع بالمعدود وتعرض تسليم المسؤولية.

ملف الحادث فيه مسار إصلاح ومسار تحصيل مستقلان. ملف المخالفة يقترح الكراء المطابق لوقت الواقعة، بلا تحميل الدين آلياً. الإرجاع والتصحيح والاقتطاع كيمرو من الاعتماد المناسب.

## الموقع العمومي

الموقع فيه الصفحة الرئيسية، الأنواع المتاحة للطلب، تفاصيل النوع، نموذج الطلب، صفحة التوصل بالطلب، التواصل والشروط والخصوصية. الدخول لحساب الزبون ماشي شرط فالأول، وما نحتاجوش بوابة زبناء كاملة.

التصميم البصري الموجود فالمشروع يقدر يوجه صور السيارات والبساطة والألوان فالموقع. لوحة التسيير كتحتاج كثافة معلومات أوضح وحالات مكتوبة وألواناً مساعدة، وما نتبعوش فيها قواعد تسويقية كتمنع علامات الخطأ أو الجداول المقروءة.

العربية خاصها اتجاه صحيح وترجمة كاملة، بما فيها الأخطاء والرسائل والوثائق. صفحات الخادم مناسبة لعرض المحتوى من أول تحميل؛ عناوين الصفحات واللغة والروابط المنظمة كتكون مضبوطة. [مرجع الترجمة](https://laravel.com/docs/localization)

إرسال الطلب يعطي مرجعاً ورسالة بأنه غير مؤكد، ماشي وصلاً بالأداء. ما نكشفوش بيانات زبون عبر رقم متسلسل أو رابط قابل للتخمين. روابط الوثائق المؤقتة كتمر من تحقق مناسب، وما نحطوش بيانات حساسة داخل رمز تحقق عام.

## العلاقات الأساسية بين المعلومات

هاد خريطة مفاهيم، ماشي تصميم نهائي للجداول ولا ترحيل بيانات.

| العلاقة | شنو نحافظو عليه |
|---|---|
| الوكالة مع المستخدمين والسيارات والزبناء | الملكية والصلاحيات وعزل البيانات |
| نوع السيارة مع السيارات الفعلية | العرض والأثمنة منفصلان عن هوية الوحدة والعداد |
| الحجز مع الزبون والسائقين | صاحب الاتفاق ماشي دائماً السائق؛ السائقون المقبولون يتوثقو |
| الكراء مع فترات استعمال السيارات | كل تبديل عندو بداية ونهاية وعداد وفحص، ما نكتفيوش بتغيير رقم السيارة الحالية |
| الكراء مع بنود المستحقات | الثمن الأصلي والإضافات والتخفيضات منفصلة وغير ممسوحة |
| الكراء مع الأداءات وتخصيصها | التوصل بالمال مختلف عن تحديد المستحق؛ لا تكرار للتحصيل |
| الضمان مع حركاته وتسوياته | المبلغ المستلم والمرجع والمقتطع والمعلق، بدون خلط مع أداء الكراء |
| السيارة مع فترات التوقف | صيانة أو حادث أو تحضير، بوقت وسبب وحالة رفع المانع |
| السيارة مع القرض والأقساط والأداءات | جدول مستقل وتخصيص دقيق لكل أداء |
| المصروف مع بنوده وتوزيعه وأداءاته | فاتورة واحدة تقدر تخص عدة سيارات، والمجموع ما يتضاعفش |
| الحادث مع الكراء والإصلاح والتعويضات | تكلفة الإصلاح ما تتسجلش مرة فالحادث ومرة كمصروف آخر |
| الوثيقة مع الإصدار والتوقيع | المصدر المجمد والملف الأصلي والتعديلات محفوظون |

عدد الجداول ينتج عن هاد العلاقات، ما نضغطوش النظام فستة عشر جدولاً. الحركات المالية والتخصيصات والخصومات عندها سجلات مستقلة بدل قائمة قابلة للاستبدال داخل حقل نصي. البيانات الجامدة الخاصة بالوثيقة يمكن حفظ نسخة مجمدة منها، بلا تحويلها لمصدر حساب متغير.

## منع التعارض والتكرار

### مصدر واحد لإشغال السيارة

كنقترح سجل فترات إشغال موحد للحجوزات والصيانة والتحضير. قاعدة PostgreSQL تمنع فترتين مانعتين متداخلتين لنفس السيارة؛ الفترات نصف مفتوحة، باش نهاية فترة تقدر توافق بداية التالية بعد احتساب التحضير. هاد تعميم للضمان القديم، ماشي إزالة له. [مرجع الفترات وقيود التعارض](https://www.postgresql.org/docs/16/rangetypes.html)

تخصيص سيارة وتأكيد الحجز والتبديل والتمديد كتستعمل نفس خدمة التوفر. تحديث الحجز وفترة الإشغال والحدث كيتنفذ معاً؛ إذا شي جزء فشل كيرجع الكل، بلا تحرير جزئي للحجز القديم.

مدة التحضير تبقى فعالة بعد الرجوع، حتى لو حالة الكراء تبدلات. الصيانة الفعلية اللي تأخر خروجها كتستمر مانعة للتسليم، ما تتسالش آلياً بوقت تقديري.

السيارة الخارجة داخل المدة يمكن تخصيصها لحجز يبدأ من بعد الرجوع المتوقع والتحضير، حسب القرار الجديد. عند تجاوز موعد الرجوع، الحجوزات الجديدة كتتوقف والحجوزات القائمة المهددة كتبان للمعالجة. التخصيص والخروج والرجوع كيحتاجو قفلاً وفحصاً للحالة، لأن قيد الفترات ما كيضمنش الرجوع المادي.

التسليم ما ينجحش قبل الرجوع الفعلي والفحص والتحضير وزوال الموانع. الحجز المستقبلي على كراء مفتوح كيحتاج مراجعة المسؤول، وما كيسمحش بالتداخل. مدة التحضير الافتراضية ساعتان، والمسؤول يضبطها، والمدة المسجلة سابقاً ما تتبدلش بأثر رجعي.

### انتهاء الحجز المؤقت

نحفظو وقت نهاية المهلة. مهمة دورية كتسجل الانتهاء وتحرر الإشغال، ولكن عملية تأكيد الأداء أو تخصيص السيارة كتراجع المهلة كذلك، ما تعتمدش فقط على أن المجدول اشتغل.

عملية انتهاء المهلة وعملية تأكيد الحجز كتتقفلو على نفس السجل باش ما ينجحوش بجوج بشكل متناقض. المال المتوصل به يبقى محفوظاً حتى لو الحجز ما بقاش متاحاً، وكيظهر للمراجعة والتسوية.

### تأكيد الخروج وتسجيل الرجوع

نفس العملية كتتحقق من الصلاحية والشروط وحالة السيارة ثم تكتب الحدث. إذا تأخر الموظف فشاشة قديمة وتبدلات البيانات من بعد، خاص يرجع ملخص محدث قبل إجراء مالي أو تخصيص مهم.

نحتافظو بمرحلة الكراء وبحالة التسوية المالية كجوج معلومات منفصلة. ما نخلقوش حالة واحدة لكل تركيب ممكن ديال التأخر والضمان والخلاف والأداء. أسماء الحالات ومصفوفة الانتقالات التقنية كتتراجع قبل التنفيذ، مع حفظ كل انتقال كحدث فالمعاملة نفسها.

### العمليات المالية

الكراء والضمان والقرض والتأمين عندهم حسابات منفصلة، ولكن أي حركة فعلية ديال النقد أو البنك عندها أصل واحد وتخصيصات واضحة. الرصيد يتحسب من الحركات المعتمدة، ما يتكتبش يدوياً كشحال باقي.

اقتطاع الضمان لتسوية ضرر كيخفض الالتزام بإرجاع الضمان ويسوي نفس مستحق الضرر؛ ما يتسجلش كقبض نقدي جديد. إرجاع الضمان ما ينقصش من أداءات الكراء. الأداء ديال قسط ما يعاودش يخرج فالصندوق كمصروف آخر.

عمليات الإرجاع والخصم والتوزيع كتتقفل وقت التنفيذ، باش جوج موظفين ما يرجعوش أكثر من المتاح. كل طلب مؤثر عندو معرف يمنع التكرار وإعادة نفس الطلب ببيانات مالية مختلفة كتترفض.

الإرسال والإشعارات ما يكونوش داخل معاملة مالية مفتوحة. الطلبات الخلفية كتتسجل كعمل مطلوب قابل للاسترجاع، ومن بعد تتنفذ بعد نجاح المعاملة. خاص كشف الأعمال اللي تثبتات فالبيانات وما وصلاتش للطابور، ما نعتابروش جدولة ما بعد الحفظ ضماناً كاملاً ضد فقدان المهمة. ## العقود والفواتير والتوقيع

العقد النموذجي المرسل مرجع من شركة أخرى. وثيقتنا كتخرج من البيانات المتحقق منها والشروط المعتمدة، بلا نسخ اسم الشركة أو توقيعات الزبناء أو أرقامها.

عند الإصدار نحفظو نسخة البيانات والشروط واللغة، والملف الصادر الأصلي وبصمته. عند إعادة التحميل نقدمو نفس الملف، ما نولّدوش نسخة جديدة بترجمة أو خط مختلف. الخطأ بعد الإصدار كيتعالج بإجراء تصحيح أو وثيقة جديدة حسب نوع الوثيقة، ماشي تعديل الأصل.

رقم الفاتورة كيصدر فمعاملة مع عدادها، وما يتولدش لكل محاولة إنشاء ملف. الفاتورة عندها حالة إصدار مستقلة عن نجاح توليد الملف، مع إعادة المحاولة بنفس المرجع. سلسلة الأرقام والضرائب تتثبت مع المحاسب قبل الإطلاق.

**التوقيع المعتمد للنسخة الأولى:** وثيقة مطبوعة وموقعة يدوياً ثم ترفق نسخة واضحة ويربطها الموظف بنفس إصدار العقد، مع التحقق قبل التسليم. التوقيع على الشاشة مؤجل. ما ننسخوش توقيعاً من وثيقة سابقة. صلاحية التنزيل والتحقق والاطلاع تتسجل حسب الملف.

## الأمان والتشغيل

### إجراءات من أول نسخة

- ربط بيانات كل وكالة بصاحبها، وفشل مغلق بلا سياق وكالة، وعلاقات تمنع الربط بوكالة أخرى.
- صلاحية على كل عملية وقراءة وتصدير ووثيقة؛ مع اختبار تجاوز الواجهة وطلب البيانات مباشرة.
- سياق الوكالة فالمهام الخلفية، ومفاتيح التخزين المؤقت والملفات مرتبطة بنفس الملكية.
- حماية الجلسة والطلبات، وتحديد محاولات الدخول وإرسال الطلبات العامة، وإلغاء الجلسات عند توقيف حساب.
- اقتراح تفعيل تحقق إضافي للمسؤول من البداية، مع طريقة استرجاع محفوظة؛ ما نؤجلوش حماية حسابه مقابل بناء أتمتة غير ضرورية.
- حفظ سجل القرارات الحساسة ومراقبة الوصول للهوية، بلا نشر البيانات الحساسة فالرسائل أو سجلات الأخطاء.
- رفض تعديل أو حذف التاريخ المالي والوثائق الصادرة من حساب التشغيل العادي؛ الاستثناءات الإدارية النادرة موثقة ومحدودة.
- رفع ملفات بصيغ وأحجام محددة، تخزين خاص، وتنقية بيانات الصور غير اللازمة. مدة الحفظ ما تتثبتش على قيمة قانونية مفترضة.

### شكل الاستضافة المقترح

نشر منسق لثلاث تطبيقات داخل نفس المستودع، قاعدة PostgreSQL مدارة، Redis، تخزين الملفات، عامل مهام عادي، عامل وثائق محدود ومجدول. الموقع واللوحة والخادم يقدرو يكونو فنطاقات فرعية لنفس النطاق الرئيسي لضبط الجلسة. التغييرات فواجهة البيانات تتوافق مع الإصدارات أثناء النشر والرجوع.

هادشي ما كيحتاجش خدمات مصغرة. استضافة التطبيق يمكن تكون مُدارة إذا كانت كتدعم العمال والمتصفح المطلوب للوثائق، أو خادماً واحداً بتشغيل موثق. ما نختاروش المزود ولا خطة مدفوعة قبل التحقق من موقع البيانات والتكلفة والنسخ والامتدادات.

ملفات الواجهة كتتبنى أثناء النشر؛ العامل الخاص بالوثائق عندو حدود للذاكرة والوقت وعدد العمليات، ما يأخرش العمليات اليومية. فشل إصدار ملف يبان للمسؤول وتتعاود محاولته، ما يولدش فاتورة مكررة.

### النسخ والاسترجاع والنشر

نحدد هدف استرجاع قاعدة البيانات وهدف الملفات بشكل منفصل، مع نسخة مستقلة ومفاتيحها. ما نعتمدوش على ادعاء دعم نسخ إصدارات التخزين بلا تحقق، وما نحسبوش نسخة أسبوعية للملفات كتضمن ضياع دقائق فقط.

قبل الإطلاق نجربو استرجاع قاعدة وملفات ووثيقة صادرة ومفاتيح فعلية فبيئة منفصلة. نجربو كذلك الرجوع لنسخة تطبيق سابقة مع تغييرات بيانات متوافقة؛ الرجوع للصورة القديمة ما كيرجعش ترحيل قاعدة البيانات تلقائياً.

التنبيه على توقف المجدول، تعطل الطوابير، فشل النسخ، امتلاء التخزين وأخطاء الخدمة خاصو صاحب متابعة. عمليات الحجز والأداء تبقى قابلة للمراجعة إذا انقطعت الشبكة، وما نعلنوش نجاحاً قبل رد الخادم.

## مراحل الإنجاز ومعيار إتمام كل مرحلة

ما نوزعوش العمل على أسابيع مفترضة قبل تجربة مسار كامل. كل مرحلة عندها نتيجة تقدر تجربها وتوافق عليها، والوظائف المذكورة كلها باقية ضمن الهدف ديال النسخة الأولى.

| المرحلة | النتيجة اللي نجربو | شرط الانتقال |
|---|---|---|
| صفر | توحيد التعليمات مع Laravel وNext.js والقرارات المعتمدة، وحسم التقريب والضرائب | مرجع واحد واضح للقرارات التقنية، بلا قواعد متضاربة |
| الأولى | دخول وصلاحيات، سيارات وزبناء، أثمنة موسمية وحصص كيلومترات، بيانات تجربة | موظف يشوف غير المسموح، وبيانات وكالة تجربة ثانية ما تتسربش |
| الثانية | طلب وحجز مؤقت وتوفر وأداء كامل وتأكيد وعقد تجريبي | سباق حجزين وسباق انتهاء المهلة مع الأداء متغطّيان باختبارات حقيقية |
| الثالثة | ضمان وتسليم ورجوع وتبديل وتمديد وتسوية وفاتورة | كراء كامل من البداية للنهاية، بلا تكرار الفلوس ولا ضياع تاريخ السيارة |
| الرابعة | وثائق وصيانة وتوقف، قرض وأقساط ومصاريف وصندوق | رصيد الصندوق والأقساط والضمان صحيح، وفاتورة متعددة السيارات ما تتكررّش |
| الخامسة | حادث وتأمين ومخالفة وخلاف وتحصيل وتقارير | تكلفة وتعويض وخصم ضمان متصالحين، والسيارة تقدر ترجع للخدمة مع ملف مالي مفتوح |
| السادسة | موقع بالعربية والفرنسية وطلبات وروابط رسائل يدوية ووثائق باللغتين | طلب من الهاتف حتى التوصل بالوثيقة، بلا ترجمة ناقصة أو تأكيد مضلل |
| السابعة | تجربة تشغيل فعلية محدودة وتدريب واسترجاع ومراجعة الحسابات | مول الوكالة ينجز يوم خدمة، ونعالج الملاحظات قبل الاعتماد العام |

التصميم البصري للموقع يقدر يتوجد مبكراً، لكن ما نبنيوش نماذج منفصلة وهمية خاصنا نعاودو نربطوها من بعد. صور السيارات والهوية التجارية والمحتوى والشروط كتتجمع بالتوازي مع بناء المسار الداخلي.

## الاختبارات اللي تحمي المشروع

اختبارات قاعدة البيانات على PostgreSQL حقيقي. نركزو على الحجز المتزامن، الملكية والصلاحيات، الأداء المكرر، انتهاء المهلة، الرجوع والتحضير، التمديد المتعارض، الأثمنة الموسمية، الإرجاع والخصومات المتزامنة، القروض والمصاريف والصندوق والوثائق.

اختبارات المتصفح كتغطي طلباً عمومياً باللغتين، كراءً مباشراً، تسليماً ورجوعاً، منع موظف من قرار مالي، وتبديلاً مع حساب الكيلومترات. ما نحتاجوش اختباراً بصرياً لكل زر قبل تجربة المسار الأساسي.

نثبتو أمثلة حسابية بالسنتيم، بما فيها التعريفة اللي ما كتقسمش على ستة بدون كسر، وحدود ساعة السماح وأربع وعشرين ساعة وثمان وأربعين ساعة للإلغاء. طريقة التقريب كتتحسم قبل تنفيذ الحساب، ماشي كل شاشة تقرّب بطريقتها.

لا نسخة تجريبية ولا تقرير كيتسمّى ناجح حتى يتقارن بالحساب المتوقع. التصحيح المهم كيجي مع حالة تثبت أن الخطأ ما رجعش.

## شنو خاص الموافقة قبل البداية التقنية

١. **الاختيار الرئيسي محسوم:** Laravel وواجهتا Next.js مع TypeScript وPostgreSQL داخل مستودع واحد. ما نعاودوش نطلبو اختيار Livewire أو Inertia.

٢. **تحديث التعليمات التقنية:** توحيدها مع الأداء الكامل، التمديد بثمن الفترة الجديدة، تحديد الموظف لمبلغ الضمان واعتماد المسؤول للاقتطاع، الإشغال بعد الرجوع، ودورة التسوية المالية. الموافقة التجارية السابقة محفوظة وما كتحتاجش تعاود تتطلب.

٣. **التفاصيل الحسابية المتبقية:** تقريب السنتيم، الثمن المرجعي للتأخير فكراء متعدد الأثمنة، تقسيم يوم عابر لموسمين، الضرائب وتوزيع التقارير. اليوم أربع وعشرون ساعة ونصفه حتى اثنتي عشرة ساعة بنصف الثمن محسومان، وكذلك مهلة الحجز والإلغاء والتأخير والكيلومترات.

٤. **التشغيل:** التوقيع الورقي وإرفاق النسخة محسوم؛ باقي وثائق الوكالة والشروط والتغطية ومعالجة بيانات الهوية، ثم مزود استضافة مناسب لميزانية وموقع بيانات معلومين.

الخطوة التالية موثقة فـ[مخطط البيانات ومسار الحالات](data-and-workflow-design-ar.md)، ثم شاشات أولية قابلة للمراجعة قبل تنفيذ المسار. ما كاين حتى ترحيل بيانات أو نشر منفذ.
