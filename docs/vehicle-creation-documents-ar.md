# الوثائق عند إنشاء السيارة

تم التطبيق في ٣ نوفمبر ٢٠٢٦ بطلب المستخدم، مع إبقاء بيانات 3108 الموجودة.

- خطوة خامسة «Documents» في إنشاء السيارة فقط. تعديل السيارات الموجودة يحتفظ بالمسار الحالي في «Documents & échéances».
- الأنواع: carte grise، assurance، visite technique، vignette، feuille de circulation. الأنواع غير المختارة لا تنشئ سجلات فارغة أو وثائق صالحة وهمية.
- «Compléter plus tard» ينشئ السيارة دون وثائق عند عدم اختيار أي قطعة. يمكن أيضاً سحب اختيار قطعة غير مرسلة وإكمالها لاحقاً.
- يتم إنشاء السيارة أولاً ثم إرسال القطع إلى نفس `/vehicles/{id}/documents` الموجود؛ لا جدول إضافي ولا تغيير صلاحيات أو قواعد جاهزية.
- كل قطعة لها request_key ثابت. القطع المؤكدة لا يعاد إرسالها. إذا ضاعت الاستجابة يبقى المحتوى مقفولاً لإعادة إرسال نفس الطلب، ومن ثم الرجوع للتعديل عبر إدارة الوثائق الحالية. أخطاء validation المؤكدة تسمح بالتصحيح.
- الحفظ الجزئي يوضح أن السيارة محفوظة وأن جزءاً بقي للإتمام. لا يدّعي أن جميع العمليات نجحت، ولا ينشئ سيارة ثانية عند إعادة المحاولة.

## التحقق

- TypeScript ناجح.
- VehicleDocumentsTest: 19 اختباراً و120 تحققاً، على قاعدة PostgreSQL الاختبارية، بما فيها idempotency، التاريخ، صلاحيات الوكالة والملفات الخاصة.
- `scripts/verify-vehicle-create-documents.cjs`: إنشاء بلا وثائق، رفع، تركيز الحقل الناقص، إلغاء منتقي الملفات دون إغلاق الفورم، تنقل خمسة تبويبات، عرض 320/768/1280، وإعادة المحاولة بعد ضياع استجابة التأمين بلا تكرار.
- اختبار الواجهة في 3103 ثم 3108 عبر route مؤقت يعرض المكوّن الحقيقي مع اعتراض جميع طلبات API. حُذف المسار المؤقت بعد التحقق؛ لم تكتب الاختبارات في قاعدة 3108.
- مقارنة بصمات محتويات 88 جدولاً قبل وبعد: متطابقة. لا migration ولا حذف بيانات. نسخة ملفات الواجهة السابقة محفوظة محلياً في `.local/backups/before-vehicle-document-step-20261103-000031`.
