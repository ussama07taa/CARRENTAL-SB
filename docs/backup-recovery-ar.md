# النسخ الاحتياطي واختبار الاسترجاع — الديمو المحلي

## النطاق
`python3 scripts/demo-recovery-check.py` كيدير نسخة من الديمو `bensebih_pickup_sandbox_20261019` فقط. ما كيرجع حتى معلومة فوق قاعدة الخدمة: الاسترجاع كيدوز فـ PostgreSQL مستقل عبر Unix socket داخل مجلد خاص، بلا TCP، وكيوقف من بعد الاختبار.

النسخة كتحتوي على:
- `database.dump`: جميع جداول PostgreSQL مع القيود والفهارس والتاريخ.
- `documents.tar.gz`: جميع ملفات `storage/app`، بما فيها الوثائق والصور والعقود الأصلية.
- `application.tar.gz`: كود API وdashboard ديال نفس النسخة، باستثناء dependencies وcache وstorage؛ تثبيت dependencies من lockfiles.
- `environment.private`: الإعدادات والمفتاح الأصلي APP_KEY. ملف سري ما يتشاركش وما يدخلش Git.
- `manifest.json`: عدد السجلات وبصمة محتواها لكل جدول، وحجم وبصمة SHA-256 لكل ملف.
- `archive-checksums.json`: بصمات مكونات النسخة؛ `verification.json`: نتيجة الاسترجاع.

المجلد `.local/recovery-drills/<UTC timestamp>` خاص بصاحب النظام (umask 077). الملفات المحلية ماشي نسخة مشفرة خارج الجهاز. وجود نسخة هنا بوحدو ما كيحميش من ضياع الجهاز.

## اتساق النسخة
السكربت كياخذ SHARE locks على الجداول أثناء الحفظ: القراءات كتبقى ممكنة والكتابات كتتسنى لثواني. إذا ما قدرش ياخذ القفل خلال 10 ثواني كيوقف. كيقارن الملفات قبل وبعد الحفظ؛ أي تغيير متزامن فالوثائق كيرفض الاختبار بدل إعلان نجاح نسخة غير متناسقة. ما كيغيّرش السجلات أو الملفات الأصلية.

من بعد الاسترجاع كيقارن محتوى جميع الجداول وعدد السجلات، وبصمة كل ملف، وبنية وحالة القيود والفهارس. PostgreSQL كيعاود يصيغ بعض CHECK expressions عند restore؛ ما كنستعملوش المطابقة الحرفية للنص المعاد صياغته كدليل فقدان.

## التشغيل
من Ubuntu داخل المشروع:
```sh
python3 scripts/demo-recovery-check.py
```
السكربت كيطلب PostgreSQL 16 وأدوات pg_dump/pg_restore/initdb/pg_ctl المحلية. ما كيحتاجش sudo ولا صلاحية CREATEDB فالسيرفر ديال الديمو. إذا فشل الاختبار، ما نعتمدوش النسخة كاسترجاع متحقق؛ نراجع السجل الخاص فمجلدها. القاعدة المعزولة كتوقف فـ finally؛ مجلدها كيبقى للفحص.

## عند حادث حقيقي
1. نوقف الكتابة والـ workers ونحافظو على الحالة الحالية قبل أي استبدال.
2. نختارو آخر نسخة متحققة ونراجعو بصمات الأرشيفات؛ ممنوع restore فوق قاعدة حية بلا مراجعة ومسؤولية واضحة.
3. نرجعو القاعدة والملفات والكود لنفس الإصدار فبيئة معزولة أولاً. نحتافظو بـ APP_KEY وأسماء DB/APP_ENV أو نراجعو جذور disks، حيث بعض المسارات كتستعمل هاد الأسماء.
4. نعاودو نثبتو dependencies، ونعدّلو اتصال القاعدة فقط فنسخة الإعدادات المعزولة، ونمسحو config cache ديال البيئة السابقة. ما نشغلوش queue أو scheduler حتى نراجعو المهام المسترجعة ونمنعو إعادة تنفيذ غير مقصودة.
5. نختبرو الولوج، صلاحيات الخدام، تنزيل الأصل ديال عقد ووثيقة وصورة، ومجاميع المال. نبطل الجلسات القديمة عند التحويل الفعلي ونرجعو نطلبو تسجيل الدخول.
6. التحويل للخدمة الأصلية كيتدار بعد نجاح هاد المراجعة؛ ما كيديروش سكربت الديمو تلقائياً.

## قبل الإنتاج — باقي مطلوب
نسخ آلي بتواتر متفق عليه، نسخة مشفرة خارج الجهاز، حفظ المفتاح خارج النسخة، تنبيه عند فشل الحفظ، وسياسة احتفاظ متفق عليها. استرجاع snapshot كيرجع لحظة الحفظ فقط؛ العمليات من بعدها ما نضمنوهاش بلا إعداد WAL/PITR مناسب. ما كاين لا تفعيل تلقائي ولا ادعاء zero data loss بهاد التجربة.

## واجهة الحالة — 2026-10-30
قسم Paramètres → Sauvegardes متاح للمدير فقط عبر GET /api/v1/settings/backups. عرض الحالة لا يكشف الأرشيف أو الإعدادات السرية. الإنشاء والتحميل المشفر موضحان أسفله.
الربط التقني الصريح: BACKUP_STATUS_DIRECTORY لمجلد recovery-drills وBACKUP_STATUS_COMPANY_ID للوكالة المخولة. بدون الربط أو لوكالة أخرى ترجع حالة غير مهيأة. تطابق source_database مع قاعدة الاتصال الحالية مطلوب قبل عرض أي محاولة. واجهة الديمو مربوطة بالوكالة 1؛ لا تنقل هذا الربط تلقائياً إلى الإنتاج.
«Test réussi» يعني نتيجة الاختبار المسجلة مع وجود مكونات النسخة، وليس إعادة فحص البصمات عند كل فتح. الواجهة توضح أن النسخ الآلي وخارج الجهاز غير مهيأين.

## إنشاء النسخة من الواجهة
زر Créer une sauvegarde يرسل POST /api/v1/settings/backups، محصور فالمدير وعلى قاعدة الديمو بالاسم الصريح. BACKUP_RUNNER يشير إلى scripts/backup-ui-worker.py؛ بدون تهيئته يبقى الزر غير متاح. لا تنقل هذا runner إلى الإنتاج لأنه مخصص للديمو المحلي.
العامل يستمر خارج طلب HTTP وينشر queued/copying/verifying/completed/failed داخل operation.json خاص. الواجهة تقرأ التقدم كل 3 ثوان أثناء العمل فقط. إعادة الطلب أثناء العملية ترجع نفس المعرف؛ قفل worker يمنع التنفيذ المتزامن وقفل backup يمنع تشغيل سكربت النسخ مرتين حتى من الطرفية. طلب الإنشاء يحتفظ بوصل محلي مستقل باسم request-UUID.json مع المستخدم والوكالة والتاريخ، دون عرضه للمتصفح.
إذا انقطع العامل ولم يعد قفله ممسوكاً، تظهر interrupted بعد مهلة 30 ثانية؛ التفاصيل التقنية تبقى في سجل خاص. completed لا تسجل إلا بعد نجاح سكربت الاسترجاع كاملاً.
تم اختبار إنشاء نسخة حقيقية من المتصفح ونجاح الاسترجاع المعزول بتاريخ 2026-10-30. لا توجد جدولة تلقائية أو نسخة خارج الجهاز؛ هذان الإعدادان ما زالا مطلوبين قبل الإنتاج.

## تحميل نسخة مشفرة من الواجهة
كل نسخة متحققة عندها زر Télécharger للمدير فقط. POST /api/v1/settings/backups/{stamp}/download يتحقق من ربط الوكالة وقاعدة المصدر وبصمات المكونات قبل إنشاء ZIP AES-256 مؤقت، بكلمة سر يختارها المستخدم (12–128 حرفاً مع التأكيد). الكلمة لا تحفظ ولا تدخل وصل التحميل؛ الإعدادات السرية داخل الأرشيف مشفرة مثل بقية الملفات.
الملف يضم database.dump وdocuments.tar.gz وapplication.tar.gz وenvironment.private وmanifest.json وarchive-checksums.json وverification.json، ولا يضم قاعدة اختبار الاسترجاع أو السجلات. ZIP المؤقت يحذف بعد إرسال الاستجابة. receipt خاص يسجل إعداد التنزيل، وليس دليلاً على أن المستخدم حفظ الملف بنجاح.
يفتح ببرنامج يدعم ZIP AES مثل 7-Zip. كلمة سر مفقودة لا يمكن استعادتها من التطبيق. النسخة المحلية الأصلية تبقى؛ حفظ ZIP على نفس الجهاز لا يشكل نسخة خارج الجهاز.
