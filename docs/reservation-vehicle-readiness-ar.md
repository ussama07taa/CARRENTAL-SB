# فحص السيارة عند إنشاء طلب

- فحص مبكر عند اختيار السيارة (التواريخ أولاً أو السيارة أولاً)، وقبل حفظ الطلب على الخادم.
- يوقف المتابعة عند نقص وثائق السيارة أو انتهاء صلاحيتها بتاريخ المغادرة، أو وجود مانع تشغيلي.
- الوثائق: البطاقة الرمادية، التأمين، الفحص التقني، الضريبة، ورقة السير. المرفق مطلوب للبطاقة الرمادية وورقة السير كما في فحص المغادرة الحالي؛ متطلبات باقي المرفقات لم تتغير.
- نافذة الأسباب تتيح فتح وثائق السيارة في تبويب آخر أو اختيار سيارة أخرى، ثم إعادة التحقق. تبقى تواريخ الطلب محفوظة.
- لم تتغير قواعد الدفع أو تأكيد الحجز أو فحص المغادرة الفعلية. إعادة إرسال طلب محفوظ بنفس المفتاح تعيد نفس الطلب ولو تغيرت جاهزية السيارة.
- لا تعديل لبنية قاعدة البيانات ولا صلاحيات جديدة. نُسخت ملفات الشيفرة فقط إلى نسخة 3108 بعد حفظ النسخ السابقة.

## الاختبارات

- RequestVehicleReadinessTest: نقص الوثائق، رفض الحفظ بلا سجل جزئي، اكتمالها، انتهاء التأمين، إعادة الإرسال، عزل الوكالات والكراج.
- ReservationRequestTest: ملفات السيارات في بيانات الاختبار مجهزة بالوثائق اللازمة للشرط الجديد.
- ReservationRequestConcurrencyTest: الوثائق مضافة إلى بيانات الاختبار قبل السباق.
- StartsAfterVehicleSelection: عزل شرط الإدخال الجديد في اختبارات المراحل اللاحقة التي تتعمد استعمال سيارات بوثائق ناقصة لاختبار فحص المغادرة؛ الاختبارات المباشرة لإنشاء الطلب تستعمل الخدمة الحقيقية.
- scripts/verify-request-readiness.cjs: تجربة المكون الحقيقي عبر صفحة مؤقتة مع اعتراض جميع طلبات API؛ منع المتابعة، رابط الوثائق، تغيير السيارة، إعادة التحقق وعروض 320/768/1280. لا تكتب هذه التجربة بيانات وكالة.

## نتيجة التحقق 2026-11-03

- 29 اختباراً / 282 تحققاً نجحت (الجاهزية، الطلبات، الوثائق)؛ واختبارا تزامن / 10 تحققات نجحا باستعمال الخدمة الحقيقية.
- TypeScript وتجربة الواجهة نجحا. ملفات 3108 الثمانية تطابق المصدر، وبصمات 88 جدولاً متطابقة قبل وبعد.
- الاختبار الإضافي RentalPickupTest توقف دون نتيجة في أول حالة خلال إعداد الملف؛ أُوقف ولم نعتبره ناجحاً. لا تمثل النتائج مراجعة كاملة لكل اختبارات النظام.
